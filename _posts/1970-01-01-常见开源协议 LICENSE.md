# 常见开源协议

选择开源协议是决定他人如何使用、修改和分发你的代码的关键步骤

以下是主流开源协议的对比和选型指南

### **二、按场景选择协议**
#### **1. 希望最大化代码传播**
- **推荐协议**：MIT / BSD 3-Clause  
- **特点**：  
  - 允许闭源商用，企业友好  
  - 仅要求保留版权声明  
  - 适合工具库（如前端框架、通用组件）

#### **2. 保护开源生态（禁止闭源）**
- **推荐协议**：GPL 3.0 / AGPL 3.0  
- **特点**：  
  - 衍生作品必须开源（"传染性"强）  
  - AGPL 额外要求网络服务也开源（如SaaS）  
  - 适合核心基础设施（如数据库、编译器）

#### **3. 平衡商业与开源**
- **推荐协议**：Apache 2.0  
- **特点**：  
  - 允许闭源，但需声明修改  
  - 提供明确的专利授权（企业法律风险低）  
  - 适合中间件（如大数据组件）

#### **4. 库/插件开发（允许闭源调用）**
- **推荐协议**：LGPL 3.0  
- **特点**：  
  - 动态链接闭源软件不受限  
  - 直接修改库代码仍需开源  
  - 适合底层库（如多媒体处理库）

### **三、关键决策因素**
1. **是否允许商用闭源？**  
   - 是 → MIT/BSD/Apache  
   - 否 → GPL/AGPL

2. **是否要求衍生作品开源？**  
   - 是 → GPL/AGPL/LGPL  
   - 否 → MIT/BSD/Apache

3. **是否需要专利保护？**  
   - 是 → Apache 2.0/GPL 3.0  
   - 否 → MIT/BSD

4. **是否涉及SaaS服务？**  
   - 是 → AGPL 优先  
   - 否 → 其他协议

### **四、协议文本使用规范**
1. 在项目根目录添加 `LICENSE` 文件  
2. 在代码文件头部添加声明（示例）：
   ```plaintext
   Copyright (c) [年份] [作者/组织]
   SPDX-License-Identifier: MIT
   ```
3. 使用 [SPDX标识符](https://spdx.org/licenses/) 标准化声明

### **五、常见问题解答**
**Q：能否更换已开源的协议？**  
A：需要所有贡献者同意（建议初始选择时慎重）

**Q：企业为什么害怕GPL？**  
A：因其"传染性"可能导致专有代码被迫开源

**Q：MIT和BSD有什么区别？**  
A：BSD 3-Clause 比 MIT 多一条"禁止用作者名促销"的条款
